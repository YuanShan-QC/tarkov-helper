# eval —— 检索质量评测

「召回准不准」不能靠感觉。这个目录是给检索链路建的一套可复跑评测，也是 `README` 里那个
「Top-5 命中率 50.4% → 95.4%」数字的来源。

## 两套样本，为什么要两套

| 样本 | 条数 | 特点 | 作用 |
|---|---|---|---|
| `queries.review20.gold.jsonl` | 20 | 人工写的，贴近真实玩家问法：全名、英文缩写、黑话、错字、模糊、多轮、比价 | 看**真实场景**的召回 |
| `queries.auto240.jsonl` | 240 | 从 5480 个物品里随机抽 60 个 × 4 种问法，seed 固定 | 看**覆盖广度**，防人工集太小导致的自我感觉良好 |

**这个区分是被现实打出来的。** 先用 20 条人工集测，修复前命中率 78.6%（11/14），看着还行；换 240 条自动集一测，只有 **50.4%**（121/240）。原因是人工集里的 LEDX 恰好有个英文名 `ledx-skin-transilluminator` 兜住了，而自动集覆盖到几千个普通物品，把窟窿全暴露出来。

**结论：只用人造小样本会低估问题。**

## 跑法

```bash
# 1. 导出检索结果（真跑检索，不调 LLM，约 30 秒）
backend/.venv/Scripts/python.exe eval/export_preds.py \
    --queries eval/queries.review20.gold.jsonl --k 5 --out-dir eval/results

# 2. 算指标
backend/.venv/Scripts/python.exe eval/run_eval.py \
    --queries eval/queries.review20.gold.jsonl --pred eval/results/preds_after.jsonl

# 自动集同理，把 --queries 换成 eval/queries.auto240.jsonl
```

`export_preds.py` 会同时导出 `before`（无别名库 + 中文名大小写敏感的旧逻辑）和
`after`（别名库 + 小写归一 + 匹配度排序）两组结果，所以前后对比是同一条命令跑出来的，
不是两次手工测得。

## 指标口径

- **Hit@5**：Top-5 候选里有没有正确物品。检索任务的正确率天然不看 Top-1 —— 下游会把 Top-5 一起喂给模型。
- **MRR**：正确物品排在第几位的倒数均值，衡量排序质量
- **分类型**：exact / abbr / slang / vague / typo / compare / missing 各自的表现。只看总分会掩盖「某一类全崩」

## 当前结果

| 样本 | 修复前 | 修复后 |
|---|---|---|
| 自动集 240 条 | 50.4% | **95.4%** |
| 人工集 14 条有唯一答案 | 78.6% | **92.9%** |

剩余 miss 基本都是**同名物品**：5480 个物品里 2105 个（38%）的中文全名或短名被 ≥2 个物品共用
（32 个「Twitch 2026 赛季物资箱（普通）」完全同名、32 个短名「海报」）。名字层面就不可区分，
正确处理是**反问**而不是猜。

详细报告见 `report_2026-10-27.md`。

## 一个刻意的选择

评测跑出来「油桶」查不到（数据里叫「金属燃料桶」，别名库没这条映射）。
我**没有**立刻加 `"油桶": "燃料"` —— 刚建完评测集就照着结果改，等于对着答案调参，
改完的数字就没有说服力了。要加，也得先把这条从测试集挪到训练集。
