# 检索评测报告（2026-10-27）

项目：tarkov-helper（塔科夫市场 AI 查询助手）
目的：给简历上的「Top-5 命中率 __% → __%」补上真实数字，同时找出检索环节还缺什么。

---

## 一、方法

评测对象是**检索这一环**（物品名 → 候选列表），不含 LLM 生成。这样好处是可复现、跑一次几秒钟，坏处是不衡量回答质量（那部分由另一套 12 题端到端基准负责）。

两套评测集，一难一广：

| 评测集 | 规模 | 构造方式 | 覆盖 |
|---|---|---|---|
| 人工集 `queries.review20.gold.jsonl` | 20 条（14 条有唯一答案） | 手写，模拟真实问法 | 精确名 5 / 英文缩写 3 / 黑话 3 / 比价 3 / 错字 1 / 模糊 4 / 不存在 2 |
| 自动集 `queries.auto240.jsonl` | 240 条（60 个物品 × 4 种问法） | 从 5480 个物品里随机抽 60 个，按「全名+多少钱 / 短名+价格 / 英文名+什么价 / 全名+值不值」生成 | 中文全名、中文短名、英文规范化名 |

**gold 标注**：`queries.review20.gold.jsonl` 里每条都补了真实物品 id（如 显卡 = `57347ca924597744596b4e71`）。自动集的 gold 就是抽样物品本身。

**before / after 的定义**（这是关键，必须能说清）：

- `after` = 现在的生产检索路径：`resolve_alias(kw)` → `tarkov.search(kw, 5)`
- `before` = 打这三个补丁之前的等价逻辑：**不查别名库**，且中文名按**大小写敏感**做子串匹配

两者跑同一批 query、同一个 gold，唯一的差别就是这三处改动，所以差值可以直接归因。

复现命令（在 `eval_kit/` 下，用项目 venv）：

```bash
..\tarkov-helper\backend\.venv\Scripts\python.exe export_preds.py --queries queries.review20.gold.jsonl --k 5 --out-dir .
..\tarkov-helper\backend\.venv\Scripts\python.exe gen_eval.py --items 60 --seeds 20261027
```

## 二、结果

### 自动集 240 条（更能代表整体水平）

| | Hit@5 | 剔除同名物品后 |
|---|---|---|
| before | 121/240 = **50.4%** | 77/144 = 53.5% |
| after | 229/240 = **95.4%** | **144/144 = 100%** |

### 人工集 14 条（更接近真实用户说法，但样本小）

| | Hit@5 | 未命中的 |
|---|---|---|
| before | 11/14 = **78.6%** | 油桶、GPU、BTC |
| after | 13/14 = **92.9%** | 油桶 |

**为什么人工集的 before 反而更高**：人工集里「LEDX」这类中文名带大写的物品，虽然大小写 bug 命不中中文全名，但英文规范化名 `ledx-skin-transilluminator` 兜住了，所以没暴露。自动集里大量纯英文名/短名的样本才把这 50% 的窟窿显出来。**这也说明只用人造小样本会低估问题。**

---

## 三、剩下的 11 条 miss 是什么

一句话：**全是数据里同名的物品，名字层面无法区分**，不是检索缺陷。

5480 个物品里有 **2105 个**（38%）的中文全名或短名被至少两个物品共用。典型：

| 关键词 | 同名的物品数 | 例子 |
|---|---|---|
| Twitch 2026 赛季物资箱（普通） | 32 | 32 个 id 完全同名，只有内容物不同 |
| 海报 | 32 | What You Seek 海报 / I Bear Loot 海报 / 女郎海报… 短名都叫「海报」 |
| EXFIL | 8 | Team Wendy EXFIL 头盔/盔罩的不同花色 |

剔除这 2105 个重名物品后，自动集 **144/144 = 100%**。

这恰恰是产品该有的行为：**遇到同名物品不该猜，应该反问**（现有 `_candidates_text` 已经会返回「找到多个候选物品，需要确认具体是哪个」）。所以这 11 条在「是否命中了唯一正确答案」这个口径下算 miss，在「用户最终拿到正确价格」这个口径下不算。

## 四、人工集唯一的真 miss：油桶

`油桶` → 库里 0 条命中，因为规范名是「金属燃料桶」（短名「金属桶」），玩家说「油桶」时别名库里没有这条映射。

- 端到端测试里这个问题**不会暴露**：模型会自己换词（油桶 → 汽油桶 → 燃料），最终查到「金属燃料桶」
- 但检索这一层确实是漏的

**结论：这是评测集发现的真实缺口，不是数据问题。** 加一条 `"油桶": "燃料"` 就能补上——我故意没加，因为刚建完评测集就照着它改，数字就不可信了。留给你决定。

## 五、这轮顺带修的代码（第 6 处改动）

`backend/tarkov_client.py` 的 `search()`：原来是**边扫边收集、够 5 条就返回**，等于按字典序先到先得。后果：

```
搜 "GP"  → 短名真的叫 "GP" 的那个物品排在全部命中的第 72 位
搜 "P"   → 排第 149 位
搜 "M45A1" → 第 6 位（就差一名）
```

改成**先召回全部命中，再按匹配质量排序**（`_match_tier`：完全相同 > 前缀 > 中文全名子串 > 中文短名子串 > 英文名子串，同档按长度差排）。

效果：自动集 94.2% → 95.4%，人工集不变。`pytest tests` 37 项全过。

## 六、简历怎么写

项目一「检索」那条 bullet 建议改成：

> 召回：自建 260 条评测集（覆盖中文全名/短名/英文名/黑话/错字）量化检索质量，Top-5 命中率由 50.4% 提升至 95.4%；定位到"短名被长名挤掉"的排序缺陷，改为按匹配度分档排序。

三个占位符对应的填法：

| 占位符 | 填什么 |
|---|---|
| 评测集【__】条 | 260（240 自动 + 20 人工） |
| Top-5 命中率【__%】→【__%】 | 50.4 → 95.4 |
| （对抗样本那条） | 属于项目二，还没测 |

**面试被追问时能答的四个点**：
1. 口径：命中 = 正确物品出现在 Top-5，MRR 另算
2. before 怎么定义的：关掉别名库 + 恢复大小写敏感的旧逻辑，跑同一批 query
3. 为什么两个集子数字差那么多：人工集被英文名兜底掩盖，自动集样本更广
4. 剩下 5% 为什么不算缺陷：2105 个物品名字不唯一，正确处理是反问不是猜
